## Waterfall Model
![[Building Successful Software.png]]

Looks nice! Doesn't work a lot of the time though, as it takes way too long.

There are a few outcomes:
- All features and functions as specified
	- It means the project is on time and in budget, but does not make money for the customer
- Not all features and functions as specified
	- The project is over time and budget, but makes a lot of money
- Or it gets cancelled during development
	- Can't make any money!

So how do we define success?
- Makes loads of money for the customer?
- Significant benefit for the customer?

Sometimes this is how we have to develop a project (e.g. building a house), but this is likely to fail.
- Failed tests cause implementation changes.
- Unachievable design causes design changes
- Imprecisely specified requirements change requirements
All of these changes lead to extra time required. We can try to cut costs with aggressive deadlines for example, but this ends up with increasing schedules.
## Criteria for Success
1. Personal success, motivates engineers
2. Technical success, code does what is required/designed 
3. Organisational success, or where the team/company no longer wanted

We need **all** of these for sustainability, e.g. Google
## [[Agile Development]]
- **Organisational**
	- Focuses on delivering value
	- We set expectations early, so they can cancel/modify before high spend
	- And include business experts and focus on core value
- **Technical**
	- Enhanced teamwork
	- Continuously integrate and finish features completely, in sequence helps organisational
- **Personal** 
	- Greater collaboration between, e.g., managers / developers / testers  
	-  Gives, e.g. greater control / autonomy / interaction  
	- More fun!

There are multiple versions of Agile (e.g. Extreme Programming (XP), Scrum), but they're all founded on well-established practices. For all methods, [[Test-Driven Development]] (TDD) is fundamental!
